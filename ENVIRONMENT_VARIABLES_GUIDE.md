# Scrowpoint — Complete Environment Variables Reference & Environment Usage Guide

This guide lists environment variables used across the **Scrowpoint** stack—covering the **Next.js frontend**, the **Go Core Escrow Backend**, the **Python EXIF-Stripping Media Microservice**, and **PostgreSQL**—along with exact instructions on when and how to configure them in **Local Development**, **Test / Staging (Sandbox)**, and **Production (Render)** environments.

---

## 1. Frontend Web Application (`frontend-web` — `.env.local` / deployment environment)

The frontend is a Next.js application. API requests use same-origin `/api/*` paths, which Next.js rewrites to the Go backend.

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `CORE_BACKEND_URL` | Server-side destination for Next.js `/api/*` rewrites to the Go backend | `http://localhost:8080` (default; override in `frontend-web/.env.local` if needed) | The staging Go backend URL | The deployed Go backend URL, e.g. the Render service URL |

`CORE_BACKEND_URL` is read by `next.config.ts` on the server and is not exposed to browser code. Restart/redeploy Next.js after changing it.

## 2. Go Core Escrow & State Machine Backend (`/scrowpoint_workspace/core-backend/.env`)

> **Important Note on Backend Secrets:** All variables in this table stay strictly on the server and are never exposed to the browser.

### A. Server & Database Configuration

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `PORT` | HTTP port the Go API listens on | `8080` | `8080` | `8080` (Set automatically by Render) |
| `ENV` | Runtime mode (controls log verbosity, CORS strictness, and OTP debug behavior) | `development` | `staging` or `test` | `production` |
| `DATABASE_URL` | Full PostgreSQL connection string | `postgres://postgres:postgres@localhost:5432/scrowpoint?sslmode=disable` | Ephemeral test DB or Staging Postgres URL (`?sslmode=require`) | Auto-injected by Render from `scrowpoint-db` (`fromDatabase`) |
| `DB_HOST` | Postgres hostname (if not using `DATABASE_URL`) | `localhost` (or `postgres` inside Docker Compose) | Staging DB host | Managed via `DATABASE_URL` |
| `DB_PORT` | Postgres port | `5432` | `5432` | `5432` |
| `DB_USER` | Postgres username | `postgres` | `scrowpoint_test` | `scrowpoint_user` |
| `DB_PASSWORD` | Postgres password | `postgres` | Test DB password | Auto-generated by Render |
| `DB_NAME` | Postgres database name | `scrowpoint` | `scrowpoint_test` | `scrowpoint` |
| `ALLOWED_ORIGINS` | Comma-separated CORS origins allowed to call the Go API | `http://localhost:3000` | `https://staging.scrowpoint.com` | `https://scrowpoint.com,https://scrowpoint-web.onrender.com` |

### B. Authentication, JWT & OAuth 2.0 (`Google` & `Facebook`)

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `JWT_SECRET` | HMAC-SHA256 signing secret for session tokens | Any local random string (e.g. `dev-jwt-secret-key`) | Distinct 32-byte staging secret | Cryptographically generated on Render (`generateValue: true`) |
| `JWT_EXPIRATION_HOURS` | Token lifespan before re-authentication is required | `168` (7 days) | `24` (1 day — shorter to test token expiry flows) | `168` (7 days) |
| `GOOGLE_OAUTH_CLIENT_ID` | Server-side verification of Google ID tokens on `POST /api/auth/oauth/google` | Local Google Client ID | Staging Google Client ID | Production Google Client ID |
| `GOOGLE_OAUTH_CLIENT_SECRET` | Google OAuth Client Secret for authorization code exchange | Local/Dev Google Client Secret | Staging Google Client Secret | Production Google Client Secret |
| `FACEBOOK_APP_ID` | Server-side verification of Facebook tokens on `POST /api/auth/oauth/facebook` | Facebook Test App ID | Facebook Test App ID | Production Facebook App ID |
| `FACEBOOK_APP_SECRET` | Meta App Secret used to validate `input_token` against Facebook Graph API | Facebook Test App Secret | Facebook Test App Secret | Production Facebook App Secret |

### C. Transactional Email & 6-Digit OTP Delivery (Registration & Forgot Password)

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `SMTP_HOST` | Outbound SMTP server for 6-digit registration & password reset OTPs | `localhost` (e.g. Mailpit/Mailhog on port `1025`) or `smtp.resend.com` | `smtp.mailtrap.io` or `smtp.resend.com` (Sandbox domain) | `smtp.resend.com` or `email-smtp.eu-west-1.amazonaws.com` (AWS SES) |
| `SMTP_PORT` | Outbound SMTP port | `1025` (Mailpit) or `587` (TLS) | `587` | `587` or `465` |
| `SMTP_USER` | SMTP username | `resend` (or empty for local Mailpit) | Mailtrap / Resend test user | `resend` (or SES IAM SMTP user) |
| `SMTP_PASSWORD` | SMTP password / API key | Test API key (or empty when using UI demo OTP banner) | Sandbox API key | Live Resend / AWS SES SMTP key |
| `SMTP_FROM_EMAIL` | Sender address for escrow receipts & OTP codes | `dev-security@scrowpoint.local` | `staging-security@scrowpoint.com` | `security@scrowpoint.com` |

### D. Custodial Escrow Payments (Paystack) & Biometric KYC (SmileID)

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `PAYSTACK_SECRET_KEY` | Server-side secret key for initializing escrow deposits & disbursing seller payouts | `sk_test_...` (Paystack Test Secret Key — allows simulated transfers & test cards) | `sk_test_...` (Paystack Test Secret Key — used for QA escrow dispute & release testing) | `sk_live_...` (Paystack Live Secret Key — moves real NGN funds; **only** use in Production) |
| `PAYSTACK_PUBLIC_KEY` | Paystack public key reference | `pk_test_...` | `pk_test_...` | `pk_live_...` |
| `PAYSTACK_WEBHOOK_SECRET` | Validates `x-paystack-signature` on `POST /api/webhooks/paystack` | `sk_test_...` (Tested locally with ngrok/Hookdeck) | `sk_test_...` (Point Paystack Test Webhook URL to staging backend) | `sk_live_...` (Point Paystack Live Webhook URL to production backend) |
| `SMILE_ID_PARTNER_ID` | Partner identifier for Nigerian NIN / BVN & Liveness verification | SmileID Sandbox Partner ID (e.g. `smile_partner_test_8492`) | SmileID Sandbox Partner ID | SmileID Live Partner ID |
| `SMILE_ID_API_KEY` | Secret API key for signing SmileID biometric KYC requests | SmileID Sandbox API Key | SmileID Sandbox API Key | SmileID Live API Key |
| `SMILE_ID_ENVIRONMENT` | Toggles SmileID endpoint between Sandbox and Live | `sandbox` | `sandbox` | `production` |

## 3. Python EXIF-Stripping Media Service (`/scrowpoint_workspace/media-service/.env`)

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `PORT` | Port FastAPI/Uvicorn listens on | `8000` | `8000` | `8000` |
| `ENVIRONMENT` | FastAPI runtime environment | `development` | `staging` | `production` |
| `STRIP_EXIF` | Enforces removal of GPS & camera metadata on uploaded gadget photos | `"true"` | `"true"` | `"true"` (Must always be `"true"` in production to prevent off-platform contact leaks) |
| `MAX_UPLOAD_SIZE_MB` | Maximum size per inspection photo/video upload | `"15"` | `"15"` | `"15"` |
| `STORAGE_BACKEND` | Where sanitized gadget media files are stored (`local` or `s3`) | `local` | `local` or `s3` (Staging bucket) | `s3` (AWS S3 / Cloudflare R2 recommended for persistent production storage) |
| `LOCAL_STORAGE_DIR` | Directory path when `STORAGE_BACKEND=local` | `/tmp/scrowpoint_media` | `/tmp/scrowpoint_media` | `/tmp/scrowpoint_media` |
| `AWS_S3_BUCKET` | S3 / Cloudflare R2 bucket name when `STORAGE_BACKEND=s3` | *(Not required when `STORAGE_BACKEND=local`)* | `scrowpoint-staging-media` | `scrowpoint-prod-media` |
| `AWS_ACCESS_KEY_ID` | S3 / R2 Access Key ID | *(Not required locally)* | Staging S3 Access Key | Production S3 Access Key |
| `AWS_SECRET_ACCESS_KEY` | S3 / R2 Secret Access Key | *(Not required locally)* | Staging S3 Secret Key | Production S3 Secret Key |
| `AWS_REGION` | S3 bucket region | `af-south-1` or `eu-west-1` | `eu-west-1` | `eu-west-1` (or `auto` for Cloudflare R2) |
