# Scrowpoint — Complete Environment Variables Reference & Environment Usage Guide

This guide lists environment variables used across the **Scrowpoint** stack—covering the **Next.js frontend**, the **Go Core Escrow Backend**, the **Python EXIF-Stripping Media Microservice**, and **PostgreSQL**—along with exact instructions on when and how to configure them in **Local Development**, **Test / Staging (Sandbox)**, and **Production (Render)** environments.

---

## 1. Frontend Web Application (`frontend-web` — `.env.local` / deployment environment)

The frontend is a Next.js application. API requests use same-origin `/api/*` paths, which Next.js rewrites to the Go backend.

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `CORE_BACKEND_URL` | Server-side destination for Next.js `/api/*` rewrites to the Go backend | `http://localhost:8080` (default; override in `frontend-web/.env.local` if needed) | The staging Go backend URL | The deployed Go backend URL, e.g. the Render service URL |

`CORE_BACKEND_URL` is read by `next.config.ts` on the server and is not exposed to browser code. Restart/redeploy Next.js after changing it.

## 2. Go Core Escrow & State Machine Backend (`/scrowpoint_workspace/core-backend/.env`)

> **Important Note on Backend Secrets:** All variables in this table stay strictly on the server and are never exposed to the browser.

### A. Server & Database Configuration

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `PORT` | HTTP port the Go API listens on | `8080` | `8080` | `8080` (Set automatically by Render) |
| `ENV` | Runtime mode (controls log verbosity, CORS strictness, and OTP debug behavior) | `development` | `staging` or `test` | `production` |
| `DATABASE_URL` | Full PostgreSQL connection string | `postgres://postgres:postgres@localhost:5432/scrowpoint?sslmode=disable` | Ephemeral test DB or Staging Postgres URL (`?sslmode=require`) | Auto-injected by Render from `scrowpoint-db` (`fromDatabase`) |
| `DB_HOST` | Postgres hostname (if not using `DATABASE_URL`) | `localhost` (or `postgres` inside Docker Compose) | Staging DB host | Managed via `DATABASE_URL` |
| `DB_PORT` | Postgres port | `5432` | `5432` | `5432` |
| `DB_USER` | Postgres username | `postgres` | `scrowpoint_test` | `scrowpoint_user` |
| `DB_PASSWORD` | Postgres password | `postgres` | Test DB password | Auto-generated by Render |
| `DB_NAME` | Postgres database name | `scrowpoint` | `scrowpoint_test` | `scrowpoint` |
| `ALLOWED_ORIGINS` | Comma-separated CORS origins allowed to call the Go API | `http://localhost:3000` | `https://staging.scrowpoint.com` | `https://scrowpoint.com,https://scrowpoint-web.onrender.com` |

### B. Direct video upload configuration

| Variable Name | Purpose | Local Development | Production (Render) |
| :--- | :--- | :--- | :--- |
| `S3_PRIVATE_BUCKET_NAME` | Private destination for KYC files and dispute evidence videos | Private test bucket | Private production bucket |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | Server-side credentials used to sign upload URLs and verify uploaded objects | Development credentials | Production-scoped credentials with object put/head/delete permissions |
| `S3_REGION` | S3 region (`auto` for R2) | `eu-west-1` | Bucket region or `auto` |
| `S3_ENDPOINT_URL` | Optional S3-compatible endpoint; required for R2 | Empty for AWS S3 | `https://<account-id>.r2.cloudflarestorage.com` for R2; empty for AWS |
| `MAX_VIDEO_UPLOAD_MB` | Maximum direct video upload size | `100` | `100` |

Video files are uploaded by the browser directly to the private bucket using a short-lived URL; the Go API does not relay the video bytes. The browser checks that a video is no longer than 60 seconds, and the API checks the stored object's actual content type and size after upload. The original video is retained without transcoding. Configure the private bucket's CORS policy to allow `PUT` from your frontend origin with the `Content-Type` request header; do not make this bucket public.

### C. Authentication, JWT & OAuth 2.0 (`Google` & `Facebook`)

## 3. Python EXIF-Stripping Media Service (`/scrowpoint_workspace/media-service/.env`)

| Variable Name | Purpose | Local Development (`development`) | Test / Staging (`test` / `staging`) | Production (`Render`) |
| :--- | :--- | :--- | :--- | :--- |
| `PORT` | Port FastAPI/Uvicorn listens on | `8000` | `8000` | `8000` |
| `ENVIRONMENT` | FastAPI runtime environment | `development` | `staging` | `production` |
| `STRIP_EXIF` | Enforces removal of GPS & camera metadata on uploaded gadget photos | `"true"` | `"true"` | `"true"` (Must always be `"true"` in production to prevent off-platform contact leaks) |
| `MAX_UPLOAD_SIZE_MB` | Maximum image size handled by the media image-processing service | `"15"` | `"15"` | `"15"` |
| `STORAGE_BACKEND` | Storage adapter (`local` or S3-compatible) | `local` | `local` or `s3` | `s3` |
| `LOCAL_STORAGE_DIR` | Local storage root when `STORAGE_BACKEND=local`; only listing media is served publicly | `/tmp/scrowpoint_media` | Persistent disk path or `/tmp/scrowpoint_media` | Not used when `STORAGE_BACKEND=s3` |
| `S3_PUBLIC_BUCKET_NAME` | Bucket for public listing photos | Not required for local storage | Staging public bucket | Production public-media bucket |
| `S3_PRIVATE_BUCKET_NAME` | Private bucket for KYC documents and dispute evidence | Not required for local storage | Staging private bucket | Production private-media bucket |
| `AWS_ACCESS_KEY_ID` | S3/R2 access key with access to both media buckets | Not required for local storage | Staging key | Production key |
| `AWS_SECRET_ACCESS_KEY` | S3/R2 secret key | Not required for local storage | Staging secret | Production secret |
| `S3_REGION` | S3 region (`auto` for Cloudflare R2) | `eu-west-1` when testing S3 | Bucket region or `auto` for R2 | Bucket region or `auto` for R2 |
| `S3_ENDPOINT_URL` | Optional custom S3-compatible endpoint; required for R2 | Empty for AWS S3 | Provider endpoint | `https://<account-id>.r2.cloudflarestorage.com` for R2; empty for AWS |
| `CDN_BASE_URL` | Public base URL for listing objects; never used for private files | `http://localhost:8000/media` | Public bucket/CDN URL | Public bucket custom-domain/CDN URL |
| `JWT_SECRET` | Must match the Go backend secret; used to verify admin tokens for private-file access | Same local value as core backend | Same staging secret as core backend | Reference the core backend's `JWT_SECRET` in Render |

Listing photos are stored in the public bucket and return `mediaUrl`. KYC documents and dispute evidence go to the private bucket and return a `storageKey` without a public URL. The media service's `GET /private/{storageKey}` route requires a valid admin bearer token and redirects to a five-minute signed object URL (or serves the file locally). Keep the private bucket non-public. A SmileID timeout still sets the KYC status to `manual_review_required`; the KYC submission must retain the private upload's `storageKey` for the manual reviewer to retrieve the document.
